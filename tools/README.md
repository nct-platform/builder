# mrjun toolkit — CLI for editing UNPACKED `.mrjun` exports

A standalone `python3` (3.9+, **stdlib only**) CLI so a Claude Code session can run a command
instead of hand-writing export JSON. It encodes the export's hard rules so callers can't get them wrong:

- form-control config in `properties.settings.stringValue`, table config (crud table/tree, process table) in `properties.model.stringValue`, `chart.js.plugin` config in `properties.Javascript.stringValue`, `dynaform.filter.form.plugin` config in `properties.filterFormModel.stringValue`, and `nct.tab.plugin` config in `properties.tabModel.stringValue` (the left-nav `site.kicker.plugin` menu lives in `properties.modelGroups.stringValue`; note `global.replacement.plugin` has **no** content Javascript slot — its editor mutates query parameters);
- every new node also carries the universal baseline slots `className`/`styleName`/`tagProperties` (empty STRING) like real nodes;
- new content nodes get fresh `identifier`/`uniqueIdentifier` (uuid4), `id=null`, next sibling `order`, parent `branchId`;
- rep-objects get `id=null`, are linked only by `identifier`, and carry `realmName`/`clientName`;
- `ruleType → executor` (PREDICATE→GroovyPredicate, EXECUTION_RULE→GroovyExecutionRule, VALIDATION_RULE→GroovyValidationRule);
- the real misspelling `process.table.pluin` is preserved;
- writes are atomic (temp + `os.replace`), UTF-8, `ensure_ascii=False`, and preserve the file's original
  (minified) formatting; inner JSON is always re-serialized valid.

## Usage

```
python3 mrjun.py <command> [<sub>] ... --project <unpacked-export-dir>
python3 mrjun.py --help
python3 mrjun.py <command> --help
```

`--project` defaults to `.`. Every mutating command prints a one-line confirmation with the new `identifier`.
`@file` args read a file; otherwise the value is a literal (or inline JSON where noted). Resolve `<id|name>`
by identifier first, then exact name, then unique substring (ambiguity is an error). A content **`alias` is NOT a
resolution key** — pasting the `(alias=…)` you see in `tree` / `list pages` output errors out (or, worse, silently
lands on a same-named node): pass the page **name** from `mrjun.py list pages`. The one exception is
`page set-redirect --to`, which genuinely takes an alias PATH. Resolution also scans non-page plugin nodes, so
after a `page mv` read the printed `parent 'X' -> 'Y'` line to confirm you moved the page you meant.

Entrypoint is **`mrjun.py`**; logic lives in the sibling `mrjunkit/` package.

## Importable primitives (for generators — do NOT re-implement these)

A generator script should `sys.path`-insert `tools/` and import these rather than hand-rolling equivalents.
Every one of them encodes a rule that has already cost a broken export at least once.

| Primitive | Module | What it guarantees |
|---|---|---|
| `core.regen_ids(node)` | `mrjunkit.core` | regenerates ONLY uuid-shaped identifiers; every non-uuid id is a layout anchor the runtime resolves BY NAME and is kept verbatim. Hand-rolled versions with a hardcoded allowlist caused both blank-page disasters of 2026-08 |
| `core.looks_uuid` / `core.iter_nodes` / `core.new_rep_object` / `core.set_inner_json` | `mrjunkit.core` | id shape, tree walk, the rep-object envelope (realm/client/timestamps), and JSON-in-a-string properties |
| **`db_cmds.dump_cell(v)`** | `mrjunkit.db_cmds` | one `project-db.dump` row value → the **string** the restorer can cast (bool → `"true"`, Decimal/int → text, dict/list → JSON text, `None` → SQL NULL). A JSON number here throws `ClassCastException` inside the restore, which is not a `SQLException`, so it rolls back the WHOLE schema: *"The database was NOT replaced"* |
| **`db_cmds.normalise_rows(columns, rows)`** | `mrjunkit.db_cmds` | the same for a whole table, and aligns each row's keys to `columns` (the restorer indexes positionally) |
| `db_cmds._build_ddl(schema, table, cols)` | `mrjunkit.db_cmds` | the exact `CREATE TABLE` text `db add-table` produces |
| `content_cmds.sync_crud_mirror(project, node)` | `mrjunkit.content_cmds` | keeps a table/tree/process model in step with its `rep-objects.settings[]` mirror, whose `content` must be a JSON **object** — a string there aborts the entire rep-objects import |

### Left-nav quick links (`site.kicker.plugin` / `modelGroups`)
The left navigation is a `site.kicker.plugin` content node with identifier `left-nav`; its menu (the quick-links tree) is a JSON **string** in `properties.modelGroups.stringValue` decoding to `{"pagesModel":[…]}`. ⚠️ The nav that RENDERS is the **shared** `Nct left nav` common node (`branches[0].virtualPlugins[]` → its `content`, identifier `left-nav`): every page also carries its own `site.kicker.plugin` node, but that node just points at the shared one (`linkContentIdentifier`), so the **per-page `modelGroups` are dead data — never hand-edit them**. These commands therefore edit the SHARED node only (falling back to the per-page nodes in older exports that lack the common plugin), so one edit changes the nav on every page. Expect `quicklink list` to report **one** left-nav node and `quicklink add` to report `1 left-nav node(s) updated` — that is success, not a miss. See [`../17-left-nav-quick-links.md`](../17-left-nav-quick-links.md).

| Command | When to use | Example |
|---|---|---|
| `quicklink list [--all]` | Print the quick-links tree(s). Default: the **distinct** trees, deduped; the `(on N page…)` header counts the left-nav NODES carrying that tree — normally **1**, the shared node that renders everywhere. `--all` prints per node. Groups shown as `[Name]`, internal links as `- name (-> targetIdentifier)`, external as `- name (=> url)`, indented. | `mrjun.py quicklink list --project ./app` |
| `quicklink add --page <id\|name> (--label <s> \| --label-loc <locale>=<text>…) [--group <name>] [--group-loc <locale>=<text>…] [--icon <c>] [--params <s>]` | Add an **internal** quick link (resolves `--page` to a `siteMapPage` identifier → `linkModel.identifier`, `internal:true`) by **appending** it to the shared `Nct left nav` node — the only one that renders (per-page kicker nodes are dead data, doc 17); older exports without that common plugin fall back to every populated per-page node. Fresh `uuid`, next sibling `order`, `needToBeSaved:true`, and `localizedMap.name`/`icon` covering **every** `tenant.json` locale. ⚠️ **`--label` copies ONE string into every locale** (correct only for a single-language project; on a 2+-locale project the toolkit **warns** because the UI then shows that language under all locales — doc 20). For a multilingual nav pass **`--label-loc en_US=Home --label-loc hy_AM=Տուն …`** (repeatable, per-locale). `--group` nests under that group (created with a fresh uuid + `globe` icon if missing); omit for top level. On a 2+-locale project also pass **`--group-loc <locale>=<text>`** (repeatable) or the group HEADING stays single-language (the toolkit warns). `--params` → `linkModel.params`. Idempotent. ⛔ `Pages` is the AUTHORING console group — business pages and the front door belong in business-named groups, and `Home` must be moved out of `Pages` (doc 17). | `mrjun.py quicklink add --page "Case queue" --label-loc en_US="Case queue" --label-loc hy_AM=… --group "Case management" --project ./app` |
| `quicklink add-external [--group <name>] (--label <s> \| --label-loc <locale>=<text>…) --url <https://…> [--icon <c>]` | Same as `add` but an **external** link (`internal:false`, `link:<url>`, no `identifier`). | `mrjun.py quicklink add-external --group "Case management" --label "Docs" --url https://example.com/docs --project ./app` |
| `quicklink rm --label <s>` | Remove links whose name/label matches, from the shared left-nav node (from every per-page node in an older export without it); groups are kept. | `mrjun.py quicklink rm --label "My Src" --project ./app` |

### Assets (`tenant-files/` → nct-file-storage)
Files under the bundle's `tenant-files/` round-trip into nct-file-storage: on import each is re-uploaded to `t/<newTenantId>/<relpath>` (`CmsProjectServiceImpl`). Use this to **vendor a JS library file** for an HTML Component Studio component (relpath `studio/<lib>/<file>`), then reference it with a **relative** `path` (`studio/<lib>/<file>`) in the plugin's `studioModel` — see [`../24-html-component-studio.md`](../24-html-component-studio.md). Prefer CDN `url`s; vendor only when you must.

|---|---|---|

### Global resources — the project's own files (`globalresource`)

ONE tree holds everything the project ships to the browser — scripts, stylesheets, HTML fragments, fonts, images — because that is the only arrangement in which a stylesheet's relative `url(../fonts/kit.woff2)` resolves. A **script or a stylesheet** in it can be switched on, and then loads on **every page of the project**; everything else is stored and served for whatever references it.

Two halves have to agree: the **registry** lives on each branch in `branches.json` as `globalAssets` (links and metadata only), and the **bytes** live under `tenant-files/webassets/<storageId>/` and are re-uploaded to `t/<newTenantId>/webassets/<storageId>/` on import. These commands keep the two in step — the content hash, the tenant-relative path, the folder tree, the load order and the per-branch storage id are all written for you. Do not hand-edit `globalAssets`; `validate` checks it against the files actually in the bundle. See [`../29-global-resources.md`](../29-global-resources.md).

⚠️ **Nothing ever arrives switched on** — not `add`, not `add-zip`. A file the author did not ask to load is a file nobody loads, which is what stops an import from changing what a live site serves. Use `globalresource set <name> --on`, or pass `--on` to `add`.

| Command | What | Example |
|---|---|---|
| `globalresource add <localfile> [--folder P] [--name N] [--branch B] [--on] [--by WHO]` | Copy one file in and register it. `--folder` places it in the tree (missing folders are created). Switched OFF unless `--on`. Only `.js`/`.css` can be switched on at all — an `.html`, a font or an image is served and never loaded. | `mrjun.py globalresource add ./brand.css --on --project ./app` |
| `globalresource mkdir <path> [--branch B]` | An empty folder. Folders are entities, not path prefixes: that is what lets one exist before it has contents, and what lets a whole vendored kit be switched off as a unit. | `mrjun.py globalresource mkdir vendor/charts --project ./app` |
| `globalresource add-zip <localfile.zip> [--folder NAME] [--branch B]` | Unpack an archive into **a folder of its own**, keeping its layout, and order its scripts: a demo page's own `<link>`/`<script>` order if the archive has one, else a ranked heuristic (stylesheets first, jQuery → Popper → Bootstrap, vendored dirs before app dirs) plus a dependency pass. A single wrapping `kit-1.2.3/` folder is unwrapped. Fonts and images travel with it. | `mrjun.py globalresource add-zip ./ui-kit.zip --folder uikit --project ./app` |
| `globalresource ls` | Each branch's tree, with `#N` marking what actually loads and in what order. `-` means it is switched off, or a folder above it is. | `mrjun.py globalresource ls --project ./app` |
| `globalresource set <name> [--on\|--off] [--rename N] [--skins "Dracula,Dark"] [--order N] [--branch B]` | Switch a file **or a folder** on/off, rename it (a folder takes its whole subtree and its bytes with it), move it in the load order, or limit a stylesheet to particular skins — **an empty `--skins ""` means every skin, which is the default**. | `mrjun.py globalresource set vendor --off --project ./app` |
| `globalresource rm <name> [--branch B]` | Remove a file, or a folder and everything under it — bytes included. To stop a file loading without losing it, use `--off`. | `mrjun.py globalresource rm uikit --project ./app` |

⛔ **Not for a script that belongs to ONE screen.** A global file that looks for `#my-screen` and does nothing on forty other pages still costs a request and a parse on each of them — that is an HTML Component Studio component ([`../24-html-component-studio.md`](../24-html-component-studio.md)), not this.

### Case notes (per-project knowledge, kept OUT of the reusable library)
The docs in `doc/builder/` are a **reusable library** — they must stay domain-neutral so the next project can use them unchanged. Everything you learn while building **one** project (its entities in the customer's own words, its screen inventory, why this CRUD is a tree, environment facts like realm/client/schema names, gotchas that only bite this data set) belongs to **that project**, not to the library.

`case` writes those notes into a `<project-dir>-case/` folder that is a **sibling** of the unpacked project — never inside it. `mrjun.py pack` walks only the project dir, so notes in that default folder can never be swept into the `.mrjun` you ship. ⚠️ If you override the location with `--dir`, keep it **outside** the project directory — a `--dir` pointing inside it defeats the whole point and `pack` will include the notes. Anything that would be true for *every* project is a library change instead, written with placeholders rather than this project's names.

| Command | When to use | Example |
|---|---|---|
| `case init [--dir <path>] [--force]` | Create the notes folder + a `README.md` that states what belongs there. Default folder is `<project-dir>-case`; `--dir` overrides it. Keeps an existing README unless `--force`. | `mrjun.py case init --project ./app` → `./app-case/README.md` |
| `case add --name <slug> [--title <t>] [--from <file>] [--dir <path>] [--force]` | Write one note. `--name` is the file name (`.md` added when missing, non-`[A-Za-z0-9._-]` slugified, lower-cased). Body comes from `--from <file>`, else **stdin**, else an empty stub. A body that does not start with `#` gets a `--title` heading prepended (title defaults to the slug, title-cased). Refuses to overwrite without `--force`. | `mrjun.py case add --project ./app --name 01-domain-model --title "Domain model"`<br>`… \| mrjun.py case add --project ./app --name 02-decisions` |
| `case ls [--dir <path>]` | List the notes with their sizes; tells you to run `case init` when the folder does not exist yet. | `mrjun.py case ls --project ./app` |

Suggested files: `01-domain-model.md` (entities + what each means), `02-screens.md` (page inventory), `03-decisions.md` (decision → reason), `04-environment.md` (realm/client, DB + schema names, integrations), `05-gotchas.md`.

### Session context (handing the delivered folder to the NEXT Claude Code session)
A delivered folder — `prmpt.txt`, `builder/`, `build-plan/plan.json`, the unpacked export, `<export>-case/`, the packed `.mrjun` — holds everything a *person* needs and nothing a fresh Claude Code session reads on its own: it does not know which folder is the export, that `mrjun.py` exists, which doc answers which question, or that hand-writing export JSON is how blank pages get shipped.

`handoff emit` writes the few files Claude Code loads **by itself** on startup, each one REGENERATED from what is already on disk (`inspect`, `plan.json`, the case notes, this README's routing table) — so nothing here is authored twice and nothing here can drift from the build. There is deliberately **no timestamp** in any emitted file: re-running with nothing changed produces byte-identical output, so a diff always means a real change.

Its shape is measured against the real Claude Code binary, not chosen: **exactly one skill** (a skill's `description` costs context on *every* turn, its body costs nothing until invoked — so one short description, one generous body); the description is **silently truncated at ~1535 chars** so it is capped at ~1200 with the load-bearing sentence first; the mode is **not** in the description (it says "read `./.dokie/project.json` first" and the mode lives there, because a description is baked in while the mode changes); skills are discovered **only** at `<root>/.claude/skills/<name>/SKILL.md`, exactly one level deep (two levels are silently ignored); `CLAUDE.md` is merged with every **ancestor** `CLAUDE.md`, so the emitted one says which folder it governs and the command warns when an ancestor exists; the library is **linked, never copied**. ⛔ It never emits a hook or a `.claude/settings.json` — under `claude -p` the workspace-trust gate is bypassed and project hooks run with no prompt, and this folder is handed between people.

| Command | When to use | Example |
|---|---|---|
| `handoff emit [--out <folder>] [--format claude\|markdown] [--mode build\|support] [--realm <r>] [--client <c>] [--base-url <origin>]` | Make a delivered folder resumable: writes `CLAUDE.md`, the single router skill `.claude/skills/dokie-project/SKILL.md`, machine state `.dokie/project.json`, and appends (never overwrites) `.gitignore`. `--project` is the **unpacked export dir**; `--out` defaults to its **parent** and may never be the export dir itself (`pack` would ship the handoff inside the `.mrjun`). `--format markdown` writes one plain `PROJECT-CONTEXT.md` instead and no `.claude/` plumbing. `--mode` defaults to whatever `.dokie/project.json` already records, so a re-run never silently changes a folder's mode. ⛔ **It writes no `.mcp.json` and no token file** — the connection is a separate command (`handoff mcp`) that reads the credential from STDIN. `--base-url` records the ORIGIN the project is served from (`http://host:port`, no path — a pasted `…/auth;jsessionid=…` is trimmed back to it) and the state then carries `project.liveUrl` = `<root>/<realm>/<client>`, so the address is asked for ONCE per folder. Refuses to overwrite a `CLAUDE.md` it did not write. Idempotent: re-run after any change. | `mrjun.py handoff emit --project ./work`<br>`mrjun.py handoff emit --project ./work --mode build` |
| `handoff mcp` | Write this folder's `.mcp.json` from the block pasted on **STDIN** — one folder is one project talking to one tenant, and Claude Code reads `.mcp.json` only for the directory it sits in. Takes either block the platform's Settings → Developer → MCP tokens panel offers and stores the canonical one; a pasted `npx mcp-remote` block is **unwrapped into the native HTTP transport** (Claude Code speaks HTTP itself, and `mcp-remote` refuses a plain-http host that is not literally `localhost`). MERGES — an entry already there, such as a browser driver, survives. Writes mode 600 and appends to `.gitignore`. ⛔ STDIN and never an argument: `ps` shows an argument to every user on the machine and the shell records it. Nothing prints the credential back. Then restart Claude Code once in this folder. | `<paste> \| mrjun.py handoff mcp --project ./work` |
| `handoff browser [--server chrome-devtools\|playwright]` | Add a **browser MCP server** to the same `.mcp.json` so a support session can drive the LIVE project in a real browser and test it end to end ([28](../28-support-mode-over-mcp.md) §8). Merges, so the tenant connection survives; safe to re-run. Reports a missing `node`/`npx` and the exact line that fixes it — ⛔ it installs nothing itself; the session runs that line. Servers are a fixed named set because the key becomes part of every tool name (`mcp__chrome-devtools__*`) and therefore every permission rule. **Prints WHERE to test** — `<root>/<realm>/<client>`, with realm/client taken from the MCP token's own claims (decoded, not verified: addressing, not authorization) and the origin from `--base-url` or what the folder already recorded — or names exactly which half is missing. ⛔ Stops you when the token's coordinates disagree with the folder's: the writes travel on the token, so that is a session verifying a fix here and applying it there. Then restart Claude Code once. | `mrjun.py handoff browser --project ./work`<br>`mrjun.py handoff browser --project ./work --base-url http://host:8077` |

### Integrity
| Command | When to use | Example |
|---|---|---|
| `validate` | Run the reimport checklist. ## Construction order (empty → dynamic project)

Following the entity dependency graph (each step depends only on the ones above it):

1. `db add-schema` + `db add-table` — author the business schema in `project-db.dump`.
2. `source add` — a source pointing at that schema.
3. `crud add ... --scaffold-methods` — the dynamic CRUD + its `crud_<alias>_<method>` queries (fill in the SQL).
4. `context add` (+ `context add-alias`) — one context listing every crud alias.
5. `rule add` — predicates / execution / validation rules (each carries the context).
6. `formgroup add` + `form add` — form groups and forms.
7. `page add` + `node add --model/--settings` — pages hosting `crud.table.plugin` and form-group landings.
8. `validate` then `pack` — check integrity, then re-zip for re-import.
